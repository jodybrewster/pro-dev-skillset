Use the `writing-feature-specs` skill to transform `$ARGUMENTS` into a complete feature specification. Save the output to `docs/specs/YYYY-MM-DD-<feature-name>-spec.md` and follow the skill's quality checklist before reporting back. If `$ARGUMENTS` is empty, ask the user for a one-line feature description first.
