# Astro 5 to 6 checklist

Official guide: `https://docs.astro.build/en/guides/upgrade-to/v6/`.
Astro 6.0 was released March 10, 2026.
Read the guide for the full text. This is a working checklist.

## Dependencies

- Node 22.12.0 or newer. Node 18 and 20 are dropped. Update `.nvmrc`, `engines`, CI and the host setting.
- Vite 7 and the Vite Environment API. Custom `vite` config and plugins may need changes. Rollup output file name config moved because of the Environment API.
- Zod 4. See the Zod section below.
- Shiki 4 for syntax highlighting.
- Every official server adapter has a new major for Vite 7: `@astrojs/vercel` 10, `@astrojs/cloudflare` 13, `@astrojs/node` 10, `@astrojs/netlify` 7.
- `@astrojs/mdx` 5 (Astro 6.4 or newer can use 6).
- `@astrojs/sitemap` and `@astrojs/rss` have no new major. Update them to the latest 3.x and 4.x.
- The Cloudflare adapter was rebuilt around `workerd` and has significant breaking changes. Follow the Cloudflare section of the guide if you deploy there.

## Adapter notes

`@astrojs/vercel` 10:

- The `@astrojs/vercel/serverless` and `@astrojs/vercel/static` import paths are removed. Import from `@astrojs/vercel`.
- The `edgeMiddleware` option is deprecated. Use `middlewareMode: 'edge'`.
- `experimentalStaticHeaders` is now `staticHeaders`.
- `maxDuration`, `isr`, `imageService`, `webAnalytics` and `skewProtection` remain documented adapter options.

All adapters:

- `experimental.csp` became `security.csp`.

## Content collections

- Legacy content collections are removed. The `legacy.collections` flag is gone.
- Move `src/content/config.ts` to `src/content.config.ts`.
- Every collection needs a `loader`, normally `glob({ pattern, base })` from `astro/loaders`. Drop `type: 'content'` and `type: 'data'`.
- Replace `getEntryBySlug()` and `getDataEntryById()` with `getEntry()`.
- Replace `entry.render()` with `render(entry)` imported from `astro:content`.
- Entry ids are file-name based now. Use `entry.filePath` when you need the original file name.
- Content loader API: the schema function signature is removed. Use `createSchema()` for dynamic schemas. Schema types are inferred instead of generated.

## Zod 4

- Import `z` from `astro/zod`. `astro:schema` and `z` from `astro:content` are deprecated.
- `z.string().email()` becomes `z.email()`. `z.string().url()` becomes `z.url()`. Other string formats moved the same way.
- Error options use `{ error: '...' }` instead of `{ message: '...' }`.
- Defaults now match the output type after transforms. Use `.prefault()` for the old behavior.
- Check the Zod 4 migration notes for custom refinements and error maps.

## Removed APIs and components

- `<ViewTransitions />` is removed. Use `<ClientRouter />` from `astro:transitions`. The `handleForms` prop is gone because form submission is always handled.
- `Astro.glob()` is removed. Use `getCollection()` or `import.meta.glob()` (add `eager: true` for eager loading).
- `emitESMImage()` is removed. Use `emitImageMetadata()`.
- `prefetch()` no longer takes a `with` option.
- `rewrite()` is removed from the actions context.
- Internal `astro:actions` exports (`serializeActionResult`, `deserializeActionResult`, `ACTION_ERROR_CODES`, `ActionInputError` and others) are removed. Use `getActionContext()`.
- Percent-encoding in route file names is no longer supported.
- CommonJS config files (`.cjs`, `.cts`) are not supported. Use ESM.
- The `session` `test` driver is removed.
- `astro:transitions` internals such as `createAnimationScope()` are deprecated in 6 and removed in 7.

## Deprecated now, removed later

- `Astro.site` and `Astro.generator` inside `getStaticPaths()` log a deprecation warning. Use `import.meta.env.SITE`.
- `import.meta.env.ASSETS_PREFIX`. Use `build.assetsPrefix` from `astro:config/server`.
- Session drivers given as strings. Use objects:

```js
import { defineConfig, sessionDrivers } from 'astro/config';

export default defineConfig({
  session: { driver: sessionDrivers.redis({ url: process.env.REDIS_URL }) },
});
```

## Config changes

- Remove `experimental.csp`, `experimental.fonts`, `experimental.liveContentCollections` and `experimental.failOnPrerenderConflict`. They are stable or replaced (`security.csp`, `fonts`, `prerenderConflictBehavior`).
- Remove `experimental.preserveScriptOrder`, `experimental.staticImportMetaEnv` and `experimental.headingIdCompat`. Their behavior is the default.
- `i18n.routing.redirectToDefaultLocale` now defaults to `false`.

## Changed behavior to test

- `<script>` and `<style>` tags render in declaration order.
- `import.meta.env` values are always inlined and never coerced to other types.
- Default image service crops without `fit`, never upscales and can rasterize SVG. `getImage()` throws on the client.
- Markdown heading ids keep trailing hyphens (GitHub slug compatible), so anchors may change.
- Endpoints whose URL ends in a file extension cannot be reached with a trailing slash.
- `getStaticPaths()` cannot return numeric params. Use strings.
- Route pathname normalization changed. Re-test routes with unusual characters.
- Astro components cannot render in Vitest client environments.

## Integration and adapter API changes (custom integrations)

- The `astro:ssr-manifest` virtual module is removed. Use `astro:config/server`.
- `entryPoints` is removed from the `astro:build:ssr` hook.
- `routes` is removed from `astro:build:done`. Use the `astro:routes:resolved` hook.
- HMR access patterns and the `SSRManifest` shape changed.
- Adapter authors: `NodeApp`, `loadManifest()`, `loadApp()`, `createExports()` and `start()` are deprecated. The old `app.render(request, routeData, locals)` signature is gone. Use `app.render(request, { routeData, locals })`. `app.setManifestData()` and `RouteData.generate()` are removed.

## Done when

- `npm run build`, `npx astro check` and tests pass on Node 22.12.0 or newer.
- No deprecation warnings remain from the hop.
- Anchors, images and redirects spot-checked in `astro preview`.
