# Astro 6 to 7 checklist

Official guide: `https://docs.astro.build/en/guides/upgrade-to/v7/`.
Astro 7.0 was released June 22, 2026.
Read the guide for the full text. This is a working checklist.
Finish and verify the 5 to 6 hop first (see `v6.md`).

## Dependencies

- Node stays at 22.12.0 or newer. The v7 guide adds no new floor, and the published `astro` 7 package declares `>=22.12.0`.
- Vite 8 (Rolldown-based). Check the Vite 8 migration guide at `https://vite.dev/guide/migration` if you have custom Vite plugins or config. Most sites need no changes.
- Adapters: `@astrojs/vercel` 11, `@astrojs/cloudflare` 14, `@astrojs/node` 11, `@astrojs/netlify` 8. Each declares an `astro` 7 peer range. Cloudflare 14 needs Astro 7.2 or newer and Node 11 needs 7.2.1 or newer, so use a recent 7.x.
- `@astrojs/mdx` 7 or 8. Version 8 needs Astro 7.2.6 or newer and delegates MDX processing to the configured Markdown processor.
- `@astrojs/react` 6 or 7 for React sites. Match other framework integrations by peer range.
- `@astrojs/sitemap` and `@astrojs/rss` have no new major. Keep them updated.

## Rust compiler (the likeliest source of build errors)

The Go compiler is gone and the Rust compiler (`@astrojs/compiler-rs`) is the only one.

- Unclosed non-void tags are now errors. Close every `<p>`, `<li>` and so on.
- Invalid HTML is no longer repaired. Fix invalid nesting such as block elements inside `<p>`. The browser handles it at runtime instead.
- Emitted CSS may differ cosmetically (for example `rebeccapurple` becomes `#639`).
- Remove `experimental.rustCompiler` from the config.

## compressHTML default

- `compressHTML` now defaults to `'jsx'`. Whitespace follows JSX rules.
- Adjacent inline elements on separate lines lose the whitespace between them. `<span>hello</span><em>world</em>` renders without a space.
- Fix by writing the space explicitly, as `{" "}`.
- To keep the previous behavior set `compressHTML: true`. Use `false` to keep all whitespace.

## Markdown processor

- Sätteri (`@astrojs/markdown-satteri`) is the default for `.md` and `.mdx`. `@astrojs/markdown-remark` is no longer installed by default.
- If you use remark or rehype plugins, `markdown.remarkPlugins`, `markdown.rehypePlugins` or `markdown.remarkRehype`, install `@astrojs/markdown-remark` and set the processor:

```js
import { defineConfig } from 'astro/config';
import { unified } from '@astrojs/markdown-remark';

export default defineConfig({
  markdown: { processor: unified() },
});
```

- With `@astrojs/mdx` 8, MDX uses the same processor. Use `@astrojs/markdown-remark` 7.3.0 or newer, or `@astrojs/markdown-satteri` 0.4.0 or newer.
- Compare rendered output for a few posts: heading ids, code blocks, smart punctuation, footnotes and embedded components. Compare RSS content too if feed items render Markdown.

## Reserved file name

- `src/fetch.ts` is the default entry for advanced routing. An existing file with that name conflicts.
- Rename your file, set a different entry with the top-level `fetchFile: './src/router.ts'`, or disable with `fetchFile: null`.
- `fetchFile` moved out of `experimental.advancedRouting` to the top level. The old default entry `src/app.ts` is no longer used.

## Experimental flags removed

Remove these from `astro.config.*`:

- `experimental.logger`: now top-level `logger`.
- `experimental.queuedRendering`: now the default.
- `experimental.rustCompiler`: now the default.
- `experimental.advancedRouting`: now the default.
- `experimental.cache`: move `cache` and `routeRules` to the top level.

## Removed and deprecated

- `@astrojs/db` is removed, along with the `astro db`, `astro login`, `astro logout`, `astro link` and `astro init` commands. Alternatives: `node:sqlite` (Node 22.5.0 or newer), Drizzle ORM or another database library.
- `astro:transitions` internals are removed: the `TRANSITION_*` constants, `isTransitionBeforePreparationEvent()`, `isTransitionBeforeSwapEvent()` and `createAnimationScope()`. Use the lifecycle event names directly.
- `getContainerRenderer()` from the package root of integrations is deprecated (still works with a warning). Import from the `container-renderer` entry for `@astrojs/react`, `preact`, `solid-js`, `svelte`, `vue` and `mdx`.

## Adapter notes

- `@astrojs/vercel` 11 upgrades to Vite 8 and adds a route cache provider: `cacheVercel()` from `@astrojs/vercel/cache`. Existing options such as `maxDuration` are unchanged.
- Route caching is stable in 7 with `Astro.cache`, `cache` and `routeRules`. It is optional.

## New in 7 that affects agents

- `astro dev` starts a detached background server when an AI agent is detected on macOS or Linux. It writes `.astro/dev.json` with URL, port and PID.
- Commands: `astro dev --background`, `astro dev status`, `astro dev logs [-f]`, `astro dev stop`. `astro preview --background` arrives in 7.2.
- Health endpoint: `/_astro/status`. Logs are structured JSON (`--json` flag or config).
- Opt out of automatic background mode with `ASTRO_DEV_BACKGROUND=0`.

## Done when

- `npm run build`, `npx astro check` and tests pass.
- No unclosed-tag errors remain and key pages were compared visually for whitespace changes.
- Markdown and MDX output was spot-checked after the processor change.
- The agent dev server flow (`.astro/dev.json`, `/_astro/status`) works, or `ASTRO_DEV_BACKGROUND=0` is documented for the project.
